# 致命武力2脚本批量解析工具

批量解析 SE3 引擎加密脚本文件（.evt / .msg / .dat），提取指令、对话、角色数据并导出至 Excel，每关一个文件含7个子表。

## 文件说明

| 文件 | 说明 |
|------|------|
| `script_parser.py` | 批量解析主程序（EVT / MSG / DAT 三合一） |
| `evt_instr_map.json` | EVT 指令作用映射表（外部文件，可编辑） |
| `export/` | 关卡 Excel 文件输出目录 |

## 环境要求

- Python 3.6+
- openpyxl 库（`pip install openpyxl`）

## 使用方法

### 方式一：双击运行

双击 `script_parser.py`，按提示输入脚本文件夹路径。

> 需确保系统已将 `.py` 关联到 `python.exe`（右键 → 打开方式 → 选 python.exe → 勾选"始终使用"）。程序末尾有 `input()` 等待回车，窗口不会一闪而过。

### 方式二：命令行运行

```
python script_parser.py <脚本文件夹路径>
```

程序会自动扫描文件夹中所有 `.evt`、`.msg`、`.dat` 文件并批量解析。

## 输出文件

- `export/<关卡名>.xlsx` — 每关一个 Excel 文件，包含7个子表：
  - Sheet1 **整合表** — 以 EVT 指令数据为主，整合 MSG 对话和 DAT 角色数据
  - Sheet2 **指令菜单** — EVT 一级菜单
  - Sheet3 **指令解析** — EVT 指令明细
  - Sheet4 **对话菜单** — MSG 一级菜单
  - Sheet5 **对话解析** — MSG 对话明细
  - Sheet6 **数据菜单** — DAT 一级菜单
  - Sheet7 **数据解析** — DAT 角色数据明细

## 指令作用映射

EVT 解析器通过外部 JSON 文件 `evt_instr_map.json` 加载指令作用映射，无需修改代码即可补充。

格式：

```json
{
    "0E0000000E": {"func": "条件判断跳转", "color": "00B0F0"},
    "0F0000000F": {"func": "赋值", "color": "FFC000"},
    "1400000014": "对话"
}
```

- 键为指令前缀（第0字节 + `000000` + 第4字节）
- 纯字符串值：只有指令作用，无颜色
- 对象值：`func` 为指令作用，`color` 为 RGB 十六进制颜色（可选）
- 文件不存在时所有指令作用留空

## 解析逻辑

### 加密方式

文件使用 XOR 0xFF 加密，程序自动解密后解析。

### 文件头校验

程序在解密后检查前3字节是否为 `SE3`，非 SE3 格式的文件会跳过并提示"文件格式不正确"。

### 文件头

| Offset | 长度 | 内容 |
|--------|------|------|
| 0-2 | 3字节 | 文件标识 `SE3`（解密后） |
| 10 | 1字节 | 一级菜单条目数 |

### 一级菜单

- 起始 Offset：274 (0x112)
- 每条记录 16 字节
- 字节 0-3：段ID（uint32 LE），即二级菜单在文件中的 Offset
- 字节 4-7：指令数量（uint32 LE）
- 字节 8-11：单条记录大小（uint32 LE，第一段及 DAT 使用）
- 字节 12-15：总大小（uint32 LE，第一段及 DAT 使用）
- 跳过规则：count=0、重复段ID、全零记录（第一段）

### 二级菜单

- 位于段ID对应的 Offset 处
- 每条 4 字节（uint32 LE），值为实际指令的 Offset

### EVT / MSG / DAT 差异

| | EVT | MSG | DAT |
|--|-----|-----|-----|
| 二级菜单 | 有 | 有 | 无（定长记录） |
| 第一段处理 | 定长记录（0x0442） | 否 | 否 |
| 跳过 0x0000 entry | 否 | 是 | 否 |
| 菜单 count | 原始 count | count + 1 | 原始 count |
| 记录结构 | 第一段定长 + 其余变长 | 变长指令 | 定长记录 |
| 文字解码 | 无 | Big5 繁体中文 | Big5 繁体中文 |

> MSG 的 count 实际需 +1，因为第一条 entry 通常为 0x0000（指向文件头），有效指令从第二条开始。

### 指令/记录内容范围

**EVT 第一段（0x0442，定长记录）：**
- 每条记录固定大小 = 菜单条目字节 8-11（record_size）
- 总数据大小 = 菜单条目字节 12-15（total_size）
- 全零记录自动跳过
- 整合表中：具体指令、指令作用列留空；指令内容列根据记录类型填写：
  - byte[22]=00（特殊事件）：bytes[23-24]为X坐标、bytes[25-26]为Y坐标（uint16 LE，十进制），byte[30]为跳转目标指令组序号 → 输出"移动到（X，Y）坐标时，跳转到N指令组（0xAAAA）"，括号内为对应一级菜单序号N的段ID
  - byte[22]=01（普通敌人）：指令内容留空

**EVT 其余段 / MSG（变长指令）：**
- 非末条指令：从当前指令 Offset 到下一条指令 Offset
- 段内末条指令：从当前指令 Offset 到下一个一级段的段ID

**DAT（定长记录）：**
- 每条记录固定大小 = 菜单条目字节 8-11（record_size）
- 总数据大小 = 菜单条目字节 12-15（total_size）
- 段内末条记录结束位置 = seg_id + total_size（或下一个段ID）
- 全零记录自动跳过

### DAT 角色数据字段

- 字节 0：分组（如 `01`）
- 字节 1-2：编号（如 `0104`，丢弃末尾 `00`）
- 字节 3：固定 `00`
- 字节 4-11：姓名（Big5 编码，8字节）
- 字节 24-25：X 坐标（uint16 LE）
- 字节 26-27：Y 坐标（uint16 LE）
- 场景名等纯文本记录：整条按 Big5 解码，分组和坐标留空

| `2000000020`（控制倒计时） | 留空 |

### 整合表单元格颜色

通过 `evt_instr_map.json` 中的 `color` 字段配置，值为 RGB 十六进制颜色。设置了颜色的指令对应行整行填充背景色（第一段 0x0442 的记录不应用颜色）：

| 指令 | 作用 | 颜色 |
|------|------|------|
| `0000000000` | 终止运行指令 | 红色（FF0000） |
| `0A0000000A` | 切换RPG/战斗模式 | 绿色（00CC00） |
| `0E0000000E` | 条件判断跳转 | 浅蓝色（00B0F0） |
| `0F0000000F` | 赋值 | 橙色（FFC000） |
| `1D0000001D` | FLAG操作相加 | 暗紫色（9966CC） |

JSON 格式支持两种写法：
- 纯字符串：`"1400000014": "对话"`（只有作用，无颜色）
- 对象：`"0E0000000E": {"func": "条件判断跳转", "color": "00B0F0"}`（有作用和颜色）

## 指令结构详解

### 0E0000000E — 条件判断跳转（18字节）

```
0E 00 00 00 0E [前缀] [ID低] [ID高] [操作码] [比较值] 00 00 00 [跳转目标4字节] FA
```

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0-3 | 4 | 指令头 | 固定 `0E 00 00 00` |
| 4 | 1 | 指令类型 | 固定 `0E` |
| 5 | 1 | 目标前缀 | `00`=变量，`01`=对象 |
| 6-7 | 2 | ID低中高 | 与前缀组合为3字节ID（如 `01 DE 03` = 对象03DE01） |
| 8 | 1 | 操作码 | 比较方式（见下表） |
| 9 | 1 | 比较值 | 要比较的数值 |
| 10-12 | 3 | 保留 | 固定 `00 00 00` |
| 13-16 | 4 | 跳转目标 | uint32 LE，跳转的指令序号 |
| 17 | 1 | 结束符 | 固定 `FA` |

**操作码含义：**

| 操作码 | 含义 | 出现次数 |
|--------|------|---------|
| 0x00 | 等于（==） | 1342 |
| 0x01 | 不等于（!=） | 7 |
| 0x02 | 大于（>） | 22 |
| 0x03 | 小于（<） | 4 |
| 0x04 | 大于等于（>=） | 8 |
| 0x05 | 小于等于（<=） | 13 |

**ID 字段说明：**

bytes[5-7] 作为 3 字节整体，格式为 `[前缀][ID低][ID高]`：
- 前缀 `00` = 变量，如 `00 DE 03` = 变量03DE00
- 前缀 `01` = 对象，如 `01 DE 03` = 对象03DE01
- 变量和对象的 ID 相差1（变量末位为00，对象末位为01），形成配对关系

**示例：**

```
0E 00 00 00 0E 00 78 03 00 03 00 00 00 03 00 00 00 FA
```
→ 如果变量037800 等于 3，跳转至指令3

```
0E 00 00 00 0E 01 DE 03 00 00 00 00 00 6C 00 00 00 FA
```
→ 如果对象03DE01 等于 0，跳转至指令108

### 0F0000000F — 赋值（14字节）

```
0F 00 00 00 0F [前缀] [ID低] [ID高] [操作码] [值] 00 00 00 FA
```

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0-3 | 4 | 指令头 | 固定 `0F 00 00 00` |
| 4 | 1 | 指令类型 | 固定 `0F` |
| 5 | 1 | 目标前缀 | `00`=变量，`01`=对象 |
| 6-7 | 2 | ID低中高 | 与前缀组合为3字节ID（同0E） |
| 8 | 1 | 操作码 | 运算方式（见下表） |
| 9 | 1 | 值 | 操作数 |
| 10-12 | 3 | 保留 | 固定 `00 00 00` |
| 13 | 1 | 结束符 | 固定 `FA` |

**操作码含义：**

| 操作码 | 含义 | 出现次数 |
|--------|------|---------|
| 0x00 | 赋值（=） | 866 |
| 0x01 | 加法（+=） | 134 |

**与 0E 的关系：**

0F 和 0E 结构平行，bytes[5-7] 的 ID 格式完全相同。常见组合：
- `0F 00 xx 00 01`（设置变量=1）→ `0E 00 xx 00 00`（如果变量等于0则跳转）：标志位开关
- `0F 00 xx 01 01`（变量+=1）→ `0E 00 xx 00 03`（如果变量等于3则跳转）：循环计数器
- `0F 01 xx 01 01`（对象+=1）→ `0E 01 xx 01 01`（如果对象不等于1则跳转）：只执行一次的开关

**示例：**

```
0F 00 00 00 0F 00 78 03 01 01 00 00 00 FA
```
→ 变量037800 += 1

```
0F 00 00 00 0F 00 DE 03 00 01 00 00 00 FA
```
→ 设置变量03DE00 = 1

### 1D0000001D — FLAG操作相加（变长字节）

```
1D 00 00 00 1D [前缀] [对象1低] [对象1高] [对象2低] [对象2高] ...
```

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0-3 | 4 | 指令头 | 固定 `1D 00 00 00` |
| 4 | 1 | 指令类型 | 固定 `1D` |
| 5 | 1 | 前缀 | `00`=变量，`01`=对象（同0E/0F） |
| 6-7 | 2 | 对象1 ID | uint16 LE，与前缀组合为3字节ID |
| 8-9 | 2 | 对象2 ID | uint16 LE，与前缀组合为3字节ID |

**与 0E/0F 的关系：**

1D 指令的 bytes[5-7] ID 格式与 0E/0F 完全相同，前缀 `00` 表示变量、`01` 表示对象。该指令将两个对象/变量的 FLAG 值相加。整合表中指令内容列留空。

**示例：**

```
1D 00 00 00 1D 01 DF 03 E0 03 ...
```
→ 对象03DF01 + 对象03E001 的 FLAG 值相加

### EVT 第一段（0x0442）记录结构 — 定长35字节

每条记录固定 35 字节，用于关卡敌人/事件调度：

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0-21 | 22 | 保留 | 固定全零 |
| 22 | 1 | 记录类型 | `01`=普通敌人，`00`=特殊事件 |
| 23-24 | 2 | X 坐标 | uint16 LE（特殊事件用） |
| 25-26 | 2 | Y 坐标 | uint16 LE（特殊事件用） |
| 27 | 1 | 参数3 | 普通敌人固定 `01`，特殊事件变化 |
| 28 | 1 | 参数4 | 普通敌人固定 `01`，特殊事件变化 |
| 29 | 1 | 类型标志 | 普通敌人=`01`，特殊事件=`01` |
| 30 | 1 | 关键字段 | 普通敌人=`FF`，特殊事件=跳转目标指令组序号（十进制） |
| 31 | 1 | 保留 | 普通敌人=`FF`，特殊事件=`00` |
| 32 | 1 | 编队模式 | 普通敌人=`01~0A`，特殊事件=`00` |
| 33 | 1 | 保留 | 固定 `00` |
| 34 | 1 | 序号 | 普通敌人=递增序号（0开始），特殊事件=`FF`（终止符） |

**两种记录类型：**

- **普通敌人**（byte[22]=01）：byte[30]=`FF`，byte[34]为递增序号，整合表指令内容留空
- **特殊事件**（byte[22]=00）：byte[30]为跳转目标指令组序号，对应一级菜单从0开始的序号，整合表输出"移动到（X，Y）坐标时，跳转到N指令组（0xAAAA）"

**示例：**

```
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 14 00 2C 00 07 01 01 08 00 00 00 FF
```
→ 特殊事件：移动到（20，44）坐标时，跳转到8指令组（0xAAAA）
