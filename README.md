# 致命武力2脚本批量解析工具

批量解析 SE3 引擎加密脚本文件（.evt / .msg / .dat），提取指令、对话、角色数据并导出至 Excel，同时生成关卡整合表。

## 文件说明

| 文件 | 说明 |
|------|------|
| `script_parser.py` | 批量解析主程序（EVT / MSG / DAT 三合一） |
| `evt_instr_map.json` | EVT 指令作用映射表（外部文件，可编辑） |
| `export/` | 各文件独立解析结果输出目录 |
| `mix/` | 关卡整合表输出目录 |

## 环境要求

- Python 3.6+
- openpyxl 库（`pip install openpyxl`）

## 使用方法

### 方式一：双击运行

双击 `script_parser.py`，按提示输入脚本文件夹路径。

> 需确保系统已将 `.py` 关联到 `python.exe`（右键 → 打开方式 → 选 python.exe → 勾选"始终使用"）。程序末尾有 `input()` 等待回车，窗口不会一闪而过。

### 方式二：命令行运行

```
python script_parser.py <脚本文件夹路径>
```

程序会自动扫描文件夹中所有 `.evt`、`.msg`、`.dat` 文件并批量解析。

## 输出文件

- `export/<文件名>_指令解析.xlsx` — EVT 指令解析结果
- `export/<文件名>_对话解析.xlsx` — MSG 对话解析结果
- `export/<文件名>_数据解析.xlsx` — DAT 角色数据解析结果
- `mix/<关卡名>_整合表.xlsx` — 以 EVT 为主的关卡整合表（每个关卡一个）

## 指令作用映射

EVT 解析器通过外部 JSON 文件 `evt_instr_map.json` 加载指令作用映射，无需修改代码即可补充。

格式：

```json
{
    "0E0000000E": "条件判断跳转",
    "0F0000000F": "赋值"
}
```

- 键为指令前缀（第0字节 + `000000` + 第4字节）
- 文件不存在时所有指令作用留空

## 解析逻辑

### 加密方式

文件使用 XOR 0xFF 加密，程序自动解密后解析。

### 文件头校验

程序在解密后检查前3字节是否为 `SE3`，非 SE3 格式的文件会跳过并提示"文件格式不正确"。

### 文件头

| Offset | 长度 | 内容 |
|--------|------|------|
| 0-2 | 3字节 | 文件标识 `SE3`（解密后） |
| 10 | 1字节 | 一级菜单条目数 |

### 一级菜单

- 起始 Offset：274 (0x112)
- 每条记录 16 字节
- 字节 0-3：段ID（uint32 LE），即二级菜单在文件中的 Offset
- 字节 4-7：指令数量（uint32 LE）
- 字节 8-11：单条记录大小（uint32 LE，仅 DAT）
- 字节 12-15：总大小（uint32 LE，仅 DAT）
- 跳过规则：count=0、重复段ID

### 二级菜单

- 位于段ID对应的 Offset 处
- 每条 4 字节（uint32 LE），值为实际指令的 Offset

### EVT / MSG / DAT 差异

| | EVT | MSG | DAT |
|--|-----|-----|-----|
| 二级菜单 | 有 | 有 | 无（定长记录） |
| 跳过第一段 | 是（0x0442） | 否 | 否 |
| 跳过 0x0000 entry | 否 | 是 | 否 |
| 菜单 count | 原始 count | count + 1 | 原始 count |
| 记录结构 | 变长指令 | 变长指令 | 定长记录 |
| 文字解码 | 无 | Big5 繁体中文 | Big5 繁体中文 |

> MSG 的 count 实际需 +1，因为第一条 entry 通常为 0x0000（指向文件头），有效指令从第二条开始。

### 指令/记录内容范围

**EVT / MSG（变长指令）：**
- 非末条指令：从当前指令 Offset 到下一条指令 Offset
- 段内末条指令：从当前指令 Offset 到下一个一级段的段ID

**DAT（定长记录）：**
- 每条记录固定大小 = 菜单条目字节 8-11（record_size）
- 总数据大小 = 菜单条目字节 12-15（total_size）
- 段内末条记录结束位置 = seg_id + total_size（或下一个段ID）
- 全零记录自动跳过

### DAT 角色数据字段

- 字节 0：分组（如 `01`）
- 字节 1-2：编号（如 `0104`，丢弃末尾 `00`）
- 字节 3：固定 `00`
- 字节 4-11：姓名（Big5 编码，8字节）
- 字节 24-25：X 坐标（uint16 LE）
- 字节 26-27：Y 坐标（uint16 LE）
- 场景名等纯文本记录：整条按 Big5 解码，分组和坐标留空

以 EVT 指令数据为主，整合 MSG 对话内容。

| 列 | 内容 |
|----|------|
| 二级菜单Offset | 二级菜单位置（同段只显示第一个） |
| 指令序号 | 段内序号（从0开始） |
| 指令内容(HEX) | 十六进制原始数据 |
| 具体指令 | 指令前缀（XX000000XX） |
| 指令作用 | 通过 evt_instr_map.json 映射 |
| 指令内容 | 根据指令类型解析的可读内容 |

**指令内容列规则：**

| 指令类型 | 内容 |
|---------|------|
| `0100000001`（加载角色） | DAT 中对应分组的所有姓名，用顿号分隔 |
| `0C0000000C`（出场或转向） | Big5 解码的角色名 |
| `1400000014`（对话） | 从 MSG 数据中匹配的对话文字（Big5），用双引号括起来 |
| `0E0000000E`（条件判断跳转） | 跳转至N指令 |
| `1000000010`（战场剩余数量判断） | 跳转至N指令（bytes[8-11]，十进制） |
| `1E0000001E`（播放动画） | Big5 解码的动画文件名 |
| 其他 | 留空 |

### 整合表单元格颜色

通过 `evt_instr_map.json` 中的 `color` 字段配置，值为 RGB 十六进制颜色。设置了颜色的指令对应行整行填充背景色：

| 指令 | 作用 | 颜色 |
|------|------|------|
| `0000000000` | 终止运行指令 | 红色（FF0000） |
| `0A0000000A` | 切换RPG/战斗模式 | 绿色（00CC00） |
| `0E0000000E` | 条件判断跳转 | 浅蓝色（00B0F0） |
| `0F0000000F` | 赋值 | 橙色（FFC000） |

JSON 格式支持两种写法：
- 纯字符串：`"1400000014": "对话"`（只有作用，无颜色）
- 对象：`"0E0000000E": {"func": "条件判断跳转", "color": "00B0F0"}`（有作用和颜色）

## 指令结构详解

### 0E0000000E — 条件判断跳转（18字节）

```
0E 00 00 00 0E [前缀] [ID低] [ID高] [操作码] [比较值] 00 00 00 [跳转目标4字节] FA
```

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0-3 | 4 | 指令头 | 固定 `0E 00 00 00` |
| 4 | 1 | 指令类型 | 固定 `0E` |
| 5 | 1 | 目标前缀 | `00`=变量，`01`=对象 |
| 6-7 | 2 | ID低中高 | 与前缀组合为3字节ID（如 `01 DE 03` = 对象03DE01） |
| 8 | 1 | 操作码 | 比较方式（见下表） |
| 9 | 1 | 比较值 | 要比较的数值 |
| 10-12 | 3 | 保留 | 固定 `00 00 00` |
| 13-16 | 4 | 跳转目标 | uint32 LE，跳转的指令序号 |
| 17 | 1 | 结束符 | 固定 `FA` |

**操作码含义：**

| 操作码 | 含义 | 出现次数 |
|--------|------|---------|
| 0x00 | 等于（==） | 1342 |
| 0x01 | 不等于（!=） | 7 |
| 0x02 | 大于（>） | 22 |
| 0x03 | 小于（<） | 4 |
| 0x04 | 大于等于（>=） | 8 |
| 0x05 | 小于等于（<=） | 13 |

**ID 字段说明：**

bytes[5-7] 作为 3 字节整体，格式为 `[前缀][ID低][ID高]`：
- 前缀 `00` = 变量，如 `00 DE 03` = 变量03DE00
- 前缀 `01` = 对象，如 `01 DE 03` = 对象03DE01
- 变量和对象的 ID 相差1（变量末位为00，对象末位为01），形成配对关系

**示例：**

```
0E 00 00 00 0E 00 78 03 00 03 00 00 00 03 00 00 00 FA
```
→ 如果变量037800 等于 3，跳转至指令3

```
0E 00 00 00 0E 01 DE 03 00 00 00 00 00 6C 00 00 00 FA
```
→ 如果对象03DE01 等于 0，跳转至指令108

### 0F0000000F — 赋值（14字节）

```
0F 00 00 00 0F [前缀] [ID低] [ID高] [操作码] [值] 00 00 00 FA
```

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0-3 | 4 | 指令头 | 固定 `0F 00 00 00` |
| 4 | 1 | 指令类型 | 固定 `0F` |
| 5 | 1 | 目标前缀 | `00`=变量，`01`=对象 |
| 6-7 | 2 | ID低中高 | 与前缀组合为3字节ID（同0E） |
| 8 | 1 | 操作码 | 运算方式（见下表） |
| 9 | 1 | 值 | 操作数 |
| 10-12 | 3 | 保留 | 固定 `00 00 00` |
| 13 | 1 | 结束符 | 固定 `FA` |

**操作码含义：**

| 操作码 | 含义 | 出现次数 |
|--------|------|---------|
| 0x00 | 赋值（=） | 866 |
| 0x01 | 加法（+=） | 134 |

**与 0E 的关系：**

0F 和 0E 结构平行，bytes[5-7] 的 ID 格式完全相同。常见组合：
- `0F 00 xx 00 01`（设置变量=1）→ `0E 00 xx 00 00`（如果变量等于0则跳转）：标志位开关
- `0F 00 xx 01 01`（变量+=1）→ `0E 00 xx 00 03`（如果变量等于3则跳转）：循环计数器
- `0F 01 xx 01 01`（对象+=1）→ `0E 01 xx 01 01`（如果对象不等于1则跳转）：只执行一次的开关

**示例：**

```
0F 00 00 00 0F 00 78 03 01 01 00 00 00 FA
```
→ 变量037800 += 1

```
0F 00 00 00 0F 00 DE 03 00 01 00 00 00 FA
```
→ 设置变量03DE00 = 1
